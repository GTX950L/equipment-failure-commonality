📖 共性分析 · 问题排查指南

定位真正根源 · 五步法（FACA 流程）

1
定义问题

明确结果列与 NG 判定标准（自动识别 FAIL / NG / 不良，结果列存在多个取值时自动取少数派，通常即 NG 类）。记录整体 NG 率；NG 样本建议 ≥ 30 条，更少时结论仅供趋势参考。

2
建立工序链路

源列选唯一标识（条码 / 板号 / 批号），参数层按工序先后排列（第一道工序 → 中间工序 → 终检 → FAIL）。工序顺序错了，红色路径会失去指向性。

3
读图定位分叉点

节点 / 链路越红 = 该取值 FAIL 占比越高。红色分叉的起点层，通常是根因的下游第一站——沿该层继续向源列方向逐层排查，红色分叉最早出现的那一层，即为根因所在。

4
子集交叉验证（CPK 面板）

点击红色节点自动筛选子集，对比「全量 / 子集 / 仅 OK / 仅 NG」的 CPK：子集 CPK D 级（不足）且路径红 → 参数确为根因方向，调工艺；子集 CPK A/B 级 → 红色不代表参数有问题，NG 另有其因（查批次 / 时段 / 操作）。

5
判定与闭环

用控制变量法拆解因果链（见下方方法），结论严格区分「统计相关」与「因果关系」，形成可执行的整改措施。

三个必避陷阱（均为实战教训）

陷阱一：把「症状」当「根因」

终检 / 测量参数（如封存量）与 FAIL 的相关性最强（IG≈1，排推荐第 1），但它们往往只是故障的结果——因果链「注水阀故障 → 注水量偏低 → 封存量超规 → FAIL」里，IG 最高的是最后一步。对策：上游参数（如注水阀档位）即使排名靠后，也应手动勾选，对比红色分叉的起点。

陷阱二：忽略「组合 / 交互」根因

单看每列 FAIL 率都不高、组合后 FAIL 率飙升（实测：注水阀 1/2 档单独 8.8% / 10.7%，注水量低桶单独也非极端，但两者组合 → 100% FAIL）。信息增益只衡量单列边缘相关，抓不住组合效应。对策：关注「组合线索」面板，用控制变量法逐层固定验证。

陷阱三：忽略「故障分类列」

「异常原因 / 错误代码」类列直接记录问题出在哪（封存量NG / 注水NG / 真空NG），是最直接的证据。智能推荐已将其放行至前两名，务必查看；若表中没有此类列，需从设备日志 / 维修记录补数据。

控制变量法 · 判断「谁引起谁」

因果链假设：A 异常 → B 异常 → FAIL。固定 A 正常，观察 B：若 B 不再异常 → B 是 A 的下游表现（中介效应），根因在 A；若 B 仍异常 → B 存在独立问题。
逐层向源列方向拆解，最上游仍异常的层，即为根因候选。桑基图「点击节点 → 子集筛选」天然支持这一步：固定上游取值后再看下游分布。

排查完成清单（自查）

  • NG 样本量 ≥ 30 条，结论可支撑？
  • 参数层已按工序先后排列，而非随意勾选？
  • 已定位红色分叉的起点层，并向上游排查？
  • 已查看「组合线索」与「异常原因」类故障分类列？
  • 已用 CPK 面板对可疑子集做交叉验证？
  • 已用控制变量法拆解可疑因果链？
  • 结论中已区分「统计相关」与「因果关系」？
